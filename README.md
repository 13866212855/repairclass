# 班班通智慧报修管理系统 (Smart Multimedia Classroom Repair System)

面向中小学"班班通"（多媒体教学设备、触控一体机、投影仪、电子白板、网络与音响系统）的轻量化日常报修与运维管理平台。

系统包含**双实现**：

- **主应用（React + Express）**：教师报修端 + 管理员运维后台，生产形态
- **Streamlit 孪生版（pyapp）**：同一套数据库逻辑的 Python 实现，作为多租户架构中的第一个网关子服务运行

```bash
# TL;DR 五分钟上手
双击 redeploy.bat                         # 一键构建启动（或 upload2remote.bat 部署远程）
访问 http://localhost:7859                # 教师报修端（默认租户）
访问 http://localhost:7859/admin          # 管理后台（admin / admin123）
```

## 🚀 一键部署

| 脚本 | 用途 | 部署后访问 |
|---|---|---|
| `redeploy.bat` | 本地一键构建并启动全部 3 个容器（compose） | http://localhost:7859 |
| `upload2remote.bat` | 本地构建 3 个镜像打包（单 tar）→ scp 到远程 → 按序拉起 | http://172.29.173.42:7859 |

双击 bat 即可（2 行引导器 + PowerShell 引擎，对行尾/代理/TLS 故障均有抗性）。

### 端口与容器清单

| 容器 | 镜像 | 宿主端口 | 内部端口 | 说明 |
|---|---|---|---|---|
| `repairclass-nginx` | repairclass-nginx | **7859** | 80 | 唯一入口网关，含动态租户热加载同步 |
| `repairclass` | repairclass | 无（仅内网） | 3000 | 主应用（React + Express） |

## 🏗️ 架构总览：一个域名，两层租户

系统在同一入口端口下同时承载两类"多租户"，职责分明、互不替代：

```
                       ┌────────────────────────────────────┐
 公网隧道/内网浏览器 ──→ │  :7859  repairclass-nginx（网关）   │
                       └──────┬──────────────────┬──────────┘
              【服务级租户】    │                  │    【学校级租户（行级隔离）】
        ┌──────────────────────┘                  └──────────────────────┐
        │ /       → repairclass:3000  主应用                             │
        │           ├── /            默认学校（gpzx 耿棚中学，可配置）      │
        │           ├── /?tenant=hqzx 黄桥中学（无感参数入口）              │
        │           └── /s/hqzx/     同上（路径风格，兼容旧链接）           │
        │ /pyapp/ → pyapp:8501        Streamlit 孪生版                    │
        │ /<代码>/ → 其他动态注册的容器子服务…                              │
        └────────────────────────────────────────────────────────────────┘
```

- **服务级租户（网关层）**：把*另一个程序*（独立容器）挂到同一域名子路径下，如 Streamlit 孪生版。需要容器加入 `mynet` 网络，由 nginx 反向代理；
- **学校级租户（应用层）**：*同一套程序*服务多所学校，靠数据库行级隔离（`tickets.school_id`）实现"零部署、零经费"入驻。师生只能看到自己的学校——无跨校切换入口，宛若专属定制。

## 🖥️ 使用指南

### 教师报修端

访问任意租户入口（如 `/` 或 `/?tenant=hqzx`），手机自适应：位置级联选择（区域→楼号→楼层→教室编号，全部由后台动态配置）、故障分类、现场拍照上传（Cloudinary 直传）、**智能记忆就绪**（自动预选常用位置与故障类型）、**AI 运维助手**在线自助排障、「扫码即用」二维码生成。提交后可实时查询进度并多轮追问。

### 管理后台

访问 `http://<域名>:7859/admin`（默认账号 `admin` / `admin123`），四个标签页：

- **工单记录处理**：数据看板（状态计数 + 故障类型分布 + 高发位置 TOP6 + 在管设备数，条目可点击筛选）、多轮交互时间线、状态流转与维修反馈、「设备档案」一键查看该设备全部历史；
- **位置与分类配置**：区域**动态增删、区名可编辑**；某区域楼层或教室删至为空时自动移除该区域；故障分类与说明自定义；**每所学校独立一份**（入驻时从主租户复制，子租户后台的修改不影响其他学校），系统标题仅超级后台可改；
- **大模型参数配置**：apihub 接口地址、密钥、模型选择与连通性测试；
- **子租户管理**（仅超级后台可见，见下节）。

### 子租户管理（多租户治理核心，仅超级后台）

「子租户管理」标签页只在超级后台 `/admin` 出现；校级后台（`/s/<代码>/admin` 或 `/admin?tenant=<代码>`）不包含该模块——**子租户不能再创建子子租户**。页面内两张卡片职责明确：

**① 网关子服务 · 外部容器**——把新的容器程序挂到同一域名子路径：

1. 新服务容器加入 `mynet` 网络：
   ```bash
   docker network create mynet   # 已存在则跳过
   docker run -d --name zhpj --network mynet --restart unless-stopped <镜像>
   ```
2. `/admin` → 子租户管理 → 填入：名称、子路径（如 `/zhpj/`）、容器名、容器内部端口 → 保存；
3. 约 10 秒后 `http://<域名>:7859/zhpj/` 即可访问（热加载，全程无需重启容器）。

> **接入要求**：服务应以子路径为根运行（Streamlit 加 `--server.baseUrlPath=zhpj`；Vite 设 `base: '/zhpj/'` 重新构建），否则绝对路径静态资源会逃逸。无法改造的服务需在网关配置中补充精确转发块。
> **数据原理**：子服务路由存于主应用 `tenants` 表（`/admin` 可视化维护），主应用 `/api/gateway/render` 实时渲染 nginx 配置块，网关侧 `gateway_sync.sh` 每 10 秒拉取：备份 → 原子替换 → `nginx -t` 校验 → 热重载，**校验失败自动回滚**。子路径/容器名走白名单正则，保留路径（`/api` `/admin` 等）禁止占用，杜绝配置注入。

**② 入驻学校管理**——兄弟学校"零部署、零经费"入驻同一套系统：

- 填写学校名称与代码即完成入驻，生成专属入口 `/?tenant=<代码>`（兼容 `/s/<代码>/`）；
- 任意学校可「设为默认」：直接访问 `/` 即进入该校（存 `system_config.default_school`，即时生效；默认学校受保护不可删除）；
- 工单、统计、设备档案全部按校隔离；超级后台可查看全部租户数据、按学校筛选（工单卡带学校徽标）；
- 入驻即自动生效，**无需**在网关模块重复添加——若子路径与已入驻学校代码重名，服务端直接拒绝，存量冲突行会标黄提示清理。

## 💻 本地开发

```bash
npm install          # 安装依赖
npm run dev          # 开发模式（Vite 中间件 + tsx 热重载，端口 3000）
npm run build        # 构建生产包（vite build + esbuild 打包 server）
npm run start        # 运行生产包 dist/server.cjs
```

Streamlit 孪生版本地调试：`pip install -r requirements.txt && streamlit run app.py`。

## 🗄️ 数据库

云端 Neon PostgreSQL Serverless（连接串内置，可用环境变量 `DATABASE_URL` 覆盖）。启动时自动建表：

- `tickets` — 报修工单（`school_id` 校级隔离、`teacher_name`/`phone`/`device_id`、时间戳与索引）
- `ticket_interactions` — 多轮交互时间线（管理员答复、维修照片、用户追问）
- `schools` — 入驻学校注册表（`code` 唯一入口代码、名称/副标题/启停）
- `school_config` — **按校独立配置**（school_id + key 联合主键）：每所学校的 `locations`/`issue_types` 各自一份，入驻时自动从主租户复制初始化，校级后台增删改互不影响；主租户（学校 1）继续使用全局 `system_config` 作为存储，删除学校时级联清理
- `tenants` — 网关子服务注册表（子路径唯一约束，首启自动种子 `/pyapp/`）
- `ai_settings` — 大模型连接参数（apihub 中转）
- `system_config` — 键值配置：`locations`（**zones 数组**：区域可增删、区名可编辑、楼层/教室清空自动移除区域，读取时自动兼容旧扁平格式）、`issue_types`、`system_title/subtitle`、`default_school`

## 🔧 故障排查速查

| 症状 | 原因与处理 |
|---|---|
| 构建 pip 阶段 `from versions: none` / 403 | 镜像源被拒。已内置 aliyun→tencent→official 镜像链自动轮换；如仍失败检查网络出口 |
| 构建 npm 阶段 TLS 报错（ERR_SSL_DECRYPTION_FAILED...） | 已内置抗 TLS 段（cache mount + maxsockets 1 + 重试循环）；顽固失败请清除 Docker Desktop 宿主死代理（Settings → Resources → Proxies，如 127.0.0.1:7890） |
| 网关路由 502 | 网关先于上游容器启动（nginx 启动时解析容器名）。重启网关容器即可；脚本已按"应用先、网关后"排序 |
| 改了子租户配置未生效 | 等 10 秒同步周期；若 `nginx -t` 失败会自动回滚旧配置，检查是否子路径与保留路径/学校代码冲突（面板会有提示） |
| 删不掉某学校 | 有工单的学校只能「停用」；默认学校须先把默认转给其他学校 |

## 📱 功能特性总览

1. **教师报修端**：手机自适应、级联位置选择（后台动态配置）、现场拍照上传（Cloudinary 直传）、智能记忆预选、AI 运维助手、扫码即用、进度实时查询与多轮追问。
2. **管理员运维端**：数据看板与分布统计、多轮交互时间线、状态流转与维修反馈、设备电子档案、大模型参数配置与测试、位置/分类全动态配置。
3. **多租户体系**：服务级（网关动态热加载、失败回滚、免重启）+ 学校级（`/?tenant=` 无感入口、行级数据隔离、默认租户可配置、扫码入驻），公网隧道零额外端口。

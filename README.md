# 班班通智慧报修管理系统 (Smart Multimedia Classroom Repair System)

面向中小学“班班通”（多媒体教学设备、触控一体机、投影仪、电子白板、网络与音响系统）的现代化日常报修、智能调度流转与运维管理 SaaS 平台。

系统全面融合 **`mymultenant`** 多租户架构规范（行级数据硬隔离、智能免选登录、凭据优先租户自愈、租户操作员审核与指派、并发原子抢单排他机制以及 Excel 数据报表导出）。

## 🛠️ 详细使用方法与操作手册

### 模式一：普通教师端（前台极简报修与进度跟踪）

#### 1. 提交报修工单
1. 打开系统首页（手机微信/浏览器直接扫教室二维码访问，零安装、零注册）。
2. **位置级联选择**：按提示依次点选：**区域**（如东区/西区）$\rightarrow$ **楼号** $\rightarrow$ **楼层** $\rightarrow$ **具体教室/多媒体室**（系统会自动记住上一次常用教室，无需反复选择）。
3. **选择故障类型**：点选“硬件故障”、“软件系统”、“网络问题”或“其他”。
4. **填写故障描述**：支持简明输入（如“投影仪开机亮黄灯，无画面输出”）。
5. **现场拍照（强力推荐）**：点击“拍照”或“相册”，拍摄现场故障指示灯或屏幕报错照片。
6. **登记联系方式（仅首次需填）**：首次提交输入姓名与手机号。提交成功后系统会自动为该教师建档并**绑定当前设备**，下次在该手机/电脑提交自动识别身份免填。
7. **点击「立即提交报修工单」**：工单提交至后台，初始状态自动流转为 `待派单`。

#### 2. 查询进度与多轮交互
1. 点击顶部标签切换至“**查询报修进度**”。
2. **状态实时看板**：
   - `待调度派单`：工单已由系统受理，正等待租户调度操作员审核。
   - `已派工，待师傅上门`：操作员已指派责任维修工程师，卡片清晰显示**师傅姓名、电话号码及调度备注**，可点击直接拨打电话。
   - `检修中`：工程师已到场排查或正在备件。
   - `已解决`：故障已修复，展示维修完成时间与维修师傅上传的现场更换配件照片。
3. **多轮在线追问**：点击“在线追问”，输入疑问（如“第3节课前能修好吗？”），后台工程师即时收到并答复，形成完整时间轴记录。

### 模式二：租户操作员 / 调度员（工单审核与智能派单）

适用于分校或门店负责协调派单的管理员/调度人员：

1. **登录系统**：
   - 访问 `/admin` 或 `/s/<学校代码>/admin`。
   - 在“账号 / 手机号码”框输入操作员手机号，直接点击“**智能识别并登录系统**”（无需切换标签）。
2. **工单审核流程**：
   - 登录后直达专属工作台，系统已自动完成 **UI 物理裁剪**，屏蔽与调度无关的全局网关配置。
   - 待派工单会闪烁提示“**审核派单**”紫色按钮。
   - 点击“审核派单”，系统弹窗展示报修教师、教室位置、故障照片与自述。
3. **指派维修工程师**：
   - 弹窗内实时列出当前租户下所有在职维修工程师，并标注每位工程师当前的**待办负荷数**（如“待办: 0 件”）。
   - 选中合适的工程师（如张强师傅），在下方可输入调度指导备注（例如：“已协调下午第2节课课间上门更换投影灯泡”）。
   - 点击“**确认指派维修工**”，工单状态立即流转为 `已派单`，教师端与维修工端同步更新。
4. **改派机制**：
   - 若原定工程师请假或紧急外出，操作员可在工单卡片上点击“**改派**”，重新指派给其他工程师。

---

### 模式三：运维维修工程师（移动端现场检修作业）

适用于张强师傅等一线技术人员：

1. **一键免密进入工作台**：
   - 输入手机号登录后，系统会自动绑定当前手机设备（显示“已绑定当前设备”）。
   - 下次关闭页面再打开时，界面会直接显示「以“张强”身份一键进入工作台」卡片，点击即可直达。
2. **任务视图自由切换**：
   - 顶部工具栏提供 **「派发给我的任务」** 与 **「全校工单池」** 切换开关。
   - 默认展示调度员指派给自己的工单。
3. **接单与处置**：
   - 对于 `已派单` 的任务，点击“**接单开始检修**”，工单状态自动切换为 `处理中`。
   - 赶赴现场排查、更换部件后，点击工单展开抽屉：
     - 选择工单状态为 `已解决`。
     - 填写处理答复（如“已清理散热风道并更换原厂灯泡，测试开机正常”）。
     - 点击“现场拍照”，拍摄修好后的设备工作画面或故障旧件留存。
     - 点击“**保存处理结果并同步给教师端**”。
4. **并发抢单排他机制 (Atomic Claim)**：
   - 在“全校工单池”中，若看到未分配的紧急工单，工程师可点击“**主动认领**”。
   - 底层采用 SQL 级条件排他校验（`WHERE assigned_to_id IS NULL`），多名师傅同时抢单也不会造成数据覆盖冲突。

### 模式四：超级管理员 & 校级主管（综合治理与数据导出）

1. **登录与全局视角**：
   - 输入 `admin` 与管理密码登录超级管理后台。
   - 顶部提供学校切换器，可一键切换查看特定学校数据或全网大盘。
2. **导出报修数据（月度报表）**：
   - 在工单看板右上角点击 **「导出报修数据」** 按钮。
   - 弹出导出配置面板，系统自动将当前租户下的所有报修记录生成标准 Excel 文件（`.xlsx`）：
     - 包含工单编号、申报学校、设备位置、故障类别、报修教师及手机、责任工程师及电话、当前状态、报修时间、修复用时、处理反馈说明等完整字段。
     - 支持按时间范围（本月/本季度/全部）快速汇总导出，方便月度运维考核与备件预算统计。
3. **设备位置与分类动态维护**：
   - “**位置与分类配置**”标签页：支持自由新增区域（如“实验楼”）、调整楼层和教室门牌；当楼层或教室全部删除时自动清理该区域。
   - 支持停用或自定义故障类型，保存后全校教师前台即时生效。
4. **角色与人员权限管理**：
   - “**角色与会员管理**”标签页：
     - 查看所有自动注册的会员与设备绑定状态。
     - 可一键将某个教师手机号提拔/设置为 **“租户操作员 / 调度员 (operator)”** 或 **“维修工程师 (technician)”**。
     - 遇到教师更换手机时，可点击“**解绑设备**”帮助其重置硬件绑定。
5. **子租户与网关管理**：
   - 填写新学校名称与英文代码，一键初始化子租户，自动生成独立二级入口，数据实现物理行级隔离。

## 🏗️ 架构规范：`mymultenant` 七大技术支柱

本项目严格贯彻 `/skills/mymultenant/` 中沉淀的多租户标准规范：

1. **行级数据硬隔离 (Single DB, Row-Level Isolation)**：所有核心表（`tickets`, `users`, `school_config`）强依赖 `school_id`，查询与更新全程附带租户边界校验，严防越权。
2. **智能单表单登录 (Identity-Blind Smart Login)**：统一账号框，自动识别纯数字手机（一线作业员/会员）与用户名（管理员），报错脱敏防刺探。
3. **凭据优先与租户自愈 (Tenant Self-Healing)**：外部分享链接租户参数错误时，后端校验凭据后自动纠偏并重定向至真实归属租户。
4. **登录态双 Session 隔离 (Dual-Session Hygiene)**：管理员 session 与一线员工 session 隔离签名，登出自动同步清理。
5. **破坏性接口 Fail-Closed 校验**：高危配置与删除接口必须校验管理作用域，操作员与维修工角色发起一律返回 403 Forbidden。
6. **原子并发流转与抢单 (Atomic Claim)**：抢单在 SQL 层面执行乐观排他锁，杜绝两名维修师傅同时认领同一张单据。
7. **RBAC 物理级界面裁剪 (UI Clipping)**：非超级管理员访问时，彻底自 DOM 节点抹除网关、大模型、全局账密等无关敏感面板。

## 💻 本地启动与部署运维

### 方式一：Node.js 本地开发运行
```bash
# 1. 安装核心依赖
npm install

# 2. 启动全栈开发服务（Express 代理 + Vite HMR，默认端口 3000）
npm run dev

# 3. 生产构建打包
npm run build

# 4. 运行生产包
npm run start
```

### 方式二：Docker 容器化一键部署
项目自带极简部署引导批处理脚本：
- **本地部署**：双击运行 `redeploy.bat`（自动拉起 Nginx 网关、React+Express 主服务、Streamlit 孪生版共 3 个容器）。
- **远程服务器部署**：双击运行 `upload2remote.bat`（本地镜像打包 $\rightarrow$ scp 远程传输 $\rightarrow$ 远程按序启动）。

## 🗄️ 核心数据表结构

- `tickets`：报修工单核心表（含 `school_id`、`status`、`assigned_to_id`、`assigned_to_name`、`assigned_to_phone`、`dispatch_note`、`reviewed_by_id` 等派单调度字段）。
- `users`：系统统一用户与会员表（含 `phone`、`role`、`school_id`、`device_id` 硬件绑定识别码）。
- `schools`：入驻学校租户注册表。
- `school_config`：各校独立的设备位置（zones 级联配置）与故障分类。
- `ticket_interactions`：工单多轮沟通时间轴与现场处置留证照片。
- `tenants`：反向代理网关子服务动态注册表。
- `ai_settings`：智能排障大模型连接参数。
